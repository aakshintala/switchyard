- Known flakes on CI: when the only red test on a CI leg is named in an open flake ticket, and the PR touches no file in that test's crate, rerun the job with `gh run rerun <id> --failed -R aakshintala/fiber`, up to twice on the same head. Ship once it is green. Report each sighting to surveyor (`printf '%s\n' "<msg>" | bash ~/.agents/bin/inbox-send __HOME__/work/fiber-worktrees/surveyor/run/inbox lane-__N__`): ticket, test, run URL. If it is still red after two reruns, or any other test is red, it goes to flywheel.
- Local reds outside the diff: when a local check fails only on a test the PR neither adds nor edits (its test file is not in `git diff --name-only origin/main...HEAD`), even in a crate the PR changes, never rerun it locally (no scratch worktree, no solo reruns). Save the failing test's complete output (nextest's STDOUT/STDERR block for that test, with the panic line; never a summary or a tail) to run/fiber-__N__-flake-<test>.txt, send surveyor (`printf '%s\n' "<msg>" | bash ~/.agents/bin/inbox-send __HOME__/work/fiber-worktrees/surveyor/run/inbox lane-__N__`) the test name, base sha and panic line verbatim, then push and let CI judge: the known-flake rule above applies on CI, and a CI red that is not a known flake goes to flywheel. A failing test the PR adds or whose file it edits is the PR's to fix.
