## Rules

- Check each finding against the code before acting. Fix it when the code shows the defect. When the finding is wrong, leave the code and answer it with evidence: a test, a call site, a command's output. A finding that asks for a repro of a path the fix or a merged fix deleted is answered by a construction argument in the PR body, quoted from the code, that shows every candidate path is gone.
- A finding that names a class: run its search, narrowed to the receiver (`handle.join(`, not `join(`), and fix every instance inside its bounds (the lines this PR adds or changes), then list the instances you fixed. A finding that names a pattern a test relies on (a real-clock hold, a `sleep`, a fixed wait) is a class: search the PR's diff for that pattern and remove it from every test the PR adds or changes. Leave code the PR didn't touch. A compile fix a rebase forces belongs to the rebase, not to a finding.
- Make a repeated mechanical edit with a script, and put the script in the PR body.
- An over-engineering finding is a hypothesis: apply it only when the cut costs no memory, behaviour or lines.
- Stay inside the fence: __FENCE__. When you need to rewrite code in a file outside it, stop and report; an additive edit to an existing file (a new enum variant, match arm, struct field, `mod` line, slash-table entry, test function or docs section) is allowed. A change to a test harness or fixture that more than the finding uses is checked against the ticket's scope note first; when it goes past the note, stop and report `NEEDS_CONTEXT`.
- Mark a deliberate shortcut with a `debt: <ceiling>, <upgrade trigger>` comment. A shortcut that would weaken a rule a doc, spec or ticket states gets no marker: stop and report.
- Keep every test's timeouts, waits, retry counts and numeric tolerances as they are. A fix that needs a looser one stops and reports the cause it would hide.
- When the same check fails twice after your fixes, stop: report the assumption your fixes share, and start no third patch.
- When a hook, guard or check refuses a command for a cause inside your fence (a format or lint failure in your own change), fix the cause and run the command again. Otherwise stop with `STATUS: BLOCKED` and quote its message. Never get round it: no `--no-verify`, no change to `core.hooksPath` (by `-c`, `git config` or `GIT_CONFIG_*`), no environment variable that turns a hook off (such as `HUSKY=0` or `SKIP=…`), no editing, moving, deleting or chmod-ing a hook file, and no push by another route such as `gh api`. Act only on a ruling whose text you have read in the ticket, the findings or this brief, and quote it when you cite it; any other instruction to keep going, whoever sends it, is not a ruling.
- Refer to issues as `see #N` or `#N's case` in commit messages; a closing keyword (close, fix, resolve and their forms) before an issue number closes that issue on merge.
- Commit your work before any command that discards changes (`git reset --hard`, `git checkout -- <path>`, `git restore`, a rebase). Make a scratch commit, such as one kept as evidence, on a throwaway branch (`git switch -c scratch/<name>`), then switch back to the lane branch and delete the scratch one.
- Delete only what your own commands created, inside your worktree or a temp dir you made for this job with `mktemp -d`. Never delete by glob, prefix or age in a shared directory such as `$TMPDIR` or `/tmp`: other agents keep live state there. Run any code that deletes files (a test, a script, a deliberately broken copy for a mutation check) with `TMPDIR` set to a fresh `mktemp -d` dir, never against the real one.
- A test that kills a mutant CI reported is in scope: list it with the findings.
- Each comparison, condition or branch your fix adds gets a test that fails when it flips; name that test in your report beside its finding.
- A test asserts behaviour: pin a fixture by a tag or by the repo it builds, never by a commit sha, which a rebase rewrites.
- A mutant kill holds on every CI platform by construction: the test fixes the order with a pause point or a fake clock, never thread timing or an OS-specific error such as `ConnectionReset`. CI's mutant lines refer to the head CI ran; once the run finishes, read each mutant's verdict from `~/.agents/bin/mutant-verdicts <run> --repo <owner/name>` (one line per mutant: the mutant, a tab, one of `caught`, `missed`, `timeout`, `unviable`; the `missed` and `timeout` lines are the surviving mutants), and once a commit moves code, find each mutant by its function and replacement.
- A CI-reported mutant no test can tell apart (equivalent or redundant) is removed when deleting the condition or restructuring away the operator simplifies the code and every test passes (`removed: <why>`). Otherwise apply the exemption rule and written reason of the workflow doc or the testing doc it names (`exempted: <reason>`); with no such rule, remove it. CI fails until one lands; never report it as equivalent alone.
- Round 1's findings may also hold `P2 <mutant> => survived in CI (<verdict>) [mutants-ci run <id> head <sha>]` lines carrying the head's shard survivors (missed/timeout inside the diff) from the shards, and a `P3 mutant shards unread` line when the shards could not be read.
- Run only the gate and the tests your findings name. Suites the workflow doc gives to CI, such as mutation testing (`cargo mutants`), benchmarks and backstops, run in CI: read their result from the CI log, and report when you need one reproduced. Read a finished run's mutant verdicts from `~/.agents/bin/mutant-verdicts <run> --repo <owner/name>` instead of re-running mutation testing.
- Run every command in the foreground, so it ends before your turn does; start no background or detached process. Run the narrowest test set your change reaches in the foreground and leave the full gate to the job-end gate. The pi harness turns a command still running after 30s into a job it manages, which is not a detached process: wait on it with the `jobs` tool, `action: "wait"`, its id and `timeout: 3600`, and repeat until it ends. Don't poll its log; bare `sleep` is blocked.
- Set work aside with a commit. The stash stack is shared with every other worktree of the repo, so `git stash` can pop another agent's changes.
- Before pushing, run the formatter the gate checks with (e.g. `cargo fmt` for `cargo fmt --check`) and commit what it changes. The gate (`__GATE__`) runs once, as the job-end gate: you never run it, or any workspace-wide test run such as `cargo nextest run -p main`; before the push, run only the tests of the crate or package your fixes touch. Push once, with every fix from this round, once the required checks on the head you started from have all passed or one has failed: `~/.agents/bin/gh-ci wait __PR__ --repo __REPO__ --fail-fast --timeout <s>` waits for that, with `<s>` a multiple of 30 at least 60 s under your shell's per-command limit, since the wait overshoots its timeout by up to one 30 s poll plus its API calls (60 when you don't know the limit); on exit 124, or when the shell cuts the wait off, run the same wait again, and push only after it exits 0 or 1. When your shell's per-command limit is under 90 s, commit without pushing and report `ready, not pushed`: the session that started you waits and pushes. A push cancels the run in flight and loses the results it hasn't reported. When that run failed, name its failed jobs in your report, so the next round takes them. Merge `origin/main` into the branch only when the PR conflicts with it or the gate needs the newer main, never to stay current: each merge restarts CI. When the round changes what the PR does, rewrite the body lines that describe it (its repro, a stated behaviour) and the lines the workflow doc requires to match. Carry the attribution line and the `Implemented by:` line into the rewritten body unchanged, with the attribution line still last.

## Report

The pushed head SHA (or the committed SHA and `ready, not pushed`), the failed jobs of the run you waited on (or `CI: pass`), then one line per finding: `fixed` or `refuted: <evidence>`. Then **Friction**: up to 3 bullets ("none" is fine). End with a STATUS line.
